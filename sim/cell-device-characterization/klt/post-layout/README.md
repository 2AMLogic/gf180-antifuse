# Post-layout access-device probe (issue #447)

Paired schematic-vs-extracted re-run of the access-device bench (I_off, R_on)
on `klt pex` extractions of the three drawn bitcells.  This directory is the
probe's bench half; the extraction half lives under `layout/<cell>/pex/`.
Ungraded supporting evidence only -- `7.analog` is NOT cited from this probe
(array-level post-layout verification stays with the array layout; see
`signoff/README.md`).

- **Run**: `runs/20261121-073730-17c2f21/` (this README is rendered by the latest ingest)
- **Timestamp**: 2026-11-21T08:04:19Z
- **Requests**: `requests/c<N>_{schematic,extracted}/{body.spice,ioff.json,ron.json}`,
  generated by `mk_post_layout_requests.py`; corner/measurement builders reused
  verbatim from `../mk_klt_requests.py`, axes cut to the bound corner:
  I_off at `ff / 125 degC / vbl = 1.1 V` over the three OFF-gate biases;
  R_on at `ss / -40 degC / vbl = 0.9 V` at the candidate's on-gate bias, 10 MHz.
- **Legs**: schematic = the cell's fixed-geometry `lvs_reference.spice` (the same
  netlist `klt pex --reference-netlist` used; drawn geometry, no sizing overrides);
  extracted = `layout/<cell>/pex/extracted.spice` included verbatim, instantiated in
  the emitted `.SUBCKT` pin order (see each `requests/c<N>/provenance.json` for the
  ordered pin map and both DUT sha256s).  Supplies, body connection, model sections,
  solver settings and measurements are identical on both legs; `netlist_source` is
  `schematic` / `extracted`.
- **Extraction**: klayout-tools `0.9.2` (KLayout `0.30.13`), `--deck gf180mcu --pdk
  gf180mcuD --extract-only`; `body_bias.status: "biased"` for all three cells
  (full blocks quoted in each `layout/<cell>/pex/README.md`).
- **Fleet**: `klt sim --backend batch --wait-for-capacity 600`; runner klt `0.9.0`,
  client `0.9.2` (`runner_compatibility: match` on every job; job ids per row below).
- **Known representation divergence**: every drawn MOS capacitor extracts as a
  linear `C` card (deck area law), not the PDK's nonlinear `cap_*` subcircuit --
  `model_mismatch` reports the cap in `reference_only` for all three cells
  (2AMLogic/klayout-tools#7004).  I_off is a DC measurement (cap open on both
  legs); R_on at 10 MHz sees the linearised cap on the extracted leg only.
- **gmin floor**: both legs keep `.options gmin=1e-13`; I_off remains a
  gmin-floor-limited upper bound exactly as in the schematic campaign.

## Dispositions

- All three extractions are usable: access-device model, geometry and drain
  orientation match the per-cell LVS reference (evidence quoted per cell in
  `layout/<cell>/pex/README.md`); `body_bias.status` is `biased` everywhere;
  parasitics present (per-net lumped R + substrate C, plus C2's coupling caps).
- No refusal occurred, so no upstream refusal link was needed; the MOS-cap
  linearisation finding is linked on 2AMLogic/klayout-tools#7004 (the runset-route
  issues #6559/#6606 cover families the curated deck cannot recognise at all --
  not this case: all device families here bind under the curated deck with `--pdk`).
- Numbers above cover exactly the drawn Minimum x Minimum split of each
  candidate's GDS (one cell per candidate; no other splits, no averaging).
