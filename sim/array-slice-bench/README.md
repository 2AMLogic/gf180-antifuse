# sim/array-slice-bench

Cornered check of the array's addressing structure on two reduced 4 x 4 slices
of the N = 32 array (`design/array/slice_*.sch`, generated by
`design/gen_array.py`), each straddling a region boundary:

| Slice | Rows | Columns | Straddles |
|---|---|---|---|
| `slice_i_ii` | 0-3 | 9-12 | Region I (Candidate 1) \| Region II (Candidate 2) |
| `slice_ii_iii` | 0-3 | 20-23 | Region II (Candidate 2) \| Region III (Candidate 3) |

Between them they cover all three regions and all four capacitor-geometry x
access-sizing sub-combinations of each (rows 0-3 x the band-relative column
pattern in `design/README.md`).

## What it confirms

1. **Selected cell reaches the BL/PL program path.** With one cell's row and
   column selects high, current flows `BLG_<band>` -> column pass-gate -> `BL_<col>`
   -> access device -> filament stand-in -> `PL_<row>_<band>` -> row return
   pass-gate -> `PLG_<band>`. Graded as `eta` (access-path current relative to
   the ideal `V_BLG / R_FIL`), return-current match `I(PLG)/I(BLG)`, `V(BL)/V(BLG)`
   and the residual `V(PL)`.
2. **Unselected cells are isolated.** Every other cell's access-path current,
   relative to its own region's ideal, split by class: same column (bit line
   powered, word line off), same row (word line on, column pass-gate off), other,
   and the idle bus of a band that holds no selected cell.
3. **The Candidate 2 band keeps drain-to-BL orientation.** Structural, from the
   derived netlists (`design/check-array.py` fails on a violation; the record
   repeats the table): `nfet_10v0_asym` `d` = `BL`, `s` = `CN`.

## Method, and what the bench stimulus is not

* The grid is a **`klt sim` request** (`testbench/<slice>_<process>.request.json`,
  generated by `make_bench.py`; one request per process corner, 5 per slice):
  3 temperatures x (16 selectable cells x 3 supply levels) = 144 operating points
  per request, 720 per slice, covering process {typical, ff, ss, fs, sf}. The supply axis scales `VDDL`, every `VDDH`, every
  `BLG` level and the select-high level together (-10 % / nominal / +10 %); the
  selected cell is a second index of the same `supply_v` sweep. On the dispatch
  workers `KLT_SIM_BACKEND=batch` sends it to the Spot batch fleet; the job id is
  in the report's `environment.remote`. `run_bench.py` never loops ngspice and
  never falls back to a local run if the batch submit fails (it prints the exact
  error and stops).
* The deck includes `design.ngspice` and `.lib`s the process corner's section of
  the 10 V LDMOS library through `$PDK_ROOT`, resolved on whichever host executes
  the corner. Why one request per process corner instead of one request with a
  process axis: the LDMOS section has to track the process corner, klt's way to
  say that is a per-section library object, and the batch fleet's runner image
  does not support it yet (the job fails with exit 1 and no usable report).
  Likewise measurements are `.meas dc` cards with lower-case names rather than
  `expr`, for the same runner-skew reason. See the PR description for the
  details and the klayout-tools issue.
* **Stimulus levels are placeholders, not programming conditions.** `BLG` is held
  at 3.0 V (Regions I, III) / 3.5 V (Region II) with `VDDH` at 5.0 / 5.5 / 5.0 V
  so the devices stay inside their rated gate voltages even at +10 %. No
  breakdown model exists (`spec/cell-candidates.md`), so nothing here says
  anything about programming voltage or yield.
* **Filament stand-in.** The stock capacitor blocks DC, so a conduction path would
  be invisible. Every cell gets a bench-only `R_FIL` = 1 Mohm across its
  capacitor in series with a 0 V sense source. It is not a post-breakdown model.
  Because *every* cell has it, any leaking access device shows up as filament
  current - the bench is deliberately worst-case for isolation.
* Thresholds (`run_bench.py`) are this bench's own acceptance numbers, stated in
  every record - not spec values.
* Geometry is the **placeholder** "min" / "2x" of `design/README.md`; no claim is
  made about the process-minimum device.
* Operating-point only. The stock moscap model does not run in transient from a
  floating-node start, and a read/program *timing* claim is out of scope here.

## Layout (follows `sim/README.md`; append-only)

```
make_bench.py                  generates testbench/ (checked: --check)
run_bench.py                   submits via klt sim, grades, writes records
testbench/tb_<slice>_<process>.spice      klt circuit body
testbench/<slice>_<process>.request.json  the klt sim request (temperature x selection x supply)
reports/<record-id>/<slice>_<process>.report.json   raw klt report (coverage id lists elided by `harness.report.elide_coverage`, sha recorded in the record)
records/<record-id>.md         evidence record
../../measurements/array-slice-bench/<record-id>.md   per-region view
```

Reports and records are never edited; a re-run mints a new `<record-id>`.

```bash
python3 sim/array-slice-bench/make_bench.py --check
python3 sim/array-slice-bench/run_bench.py        # both slices, via klt sim
```

## Full-band leakage mode (issue #70)

`python3 sim/array-slice-bench/run_bench.py --mode full-band` measures the OFF-state
addressing-stage current at the **read** bias for every column of each band
(Region I 11, II 11, III 10 columns; rows 0-3, which carry all four capacitor x
access sub-combinations). The bands are `band_i/ii/iii` in `design/gen_array.py`
(`BAND_SLICES`, kept apart from `SLICES`; netlists in `design/netlists/`). Three
variants per band and process corner (`testbench/leak_<variant>_<band>_<process>.request.json`):

| Variant | What it holds | What it reads |
|---|---|---|
| `pgoff` | every column OFF, every `BL_c` clamped to 0 V | `i(Vbl)` at the summation node and `i(Vcl_c)` per column: the OFF pass-gate worst case (cells see V_DS = 0, so the `31 x I_off` cell term is not in it) |
| `nat` | every column OFF, `BL_c` floating, no filament stand-in | natural DC steady-state current at the node |
| `sel` | one cell selected (one per cap x access sub-combination), `R_FIL` on every cell | selected-path conduction at the read level (`eta`, `V(BL)/V(BLG)`, return ratio); DC only, **settling is not evidenced** |

**Assumed, not designed here:** the sense node is the band's `BLG` bus (the legs are not
attached to the array on `main`; #73). Read levels bracket the `BL at worst` rows of
`sim/program-read-legs/records/20261015-151616-d3df921.md` per candidate (table in the
record), each at x0.9 / 1.0 / 1.1 for the VCLAMP tracking points. The `31 x I_off` cell term is
carried once from `sim/cell-device-characterization/records/` and was not re-evaluated at the 3.8-4.4 V
unprogrammed sense levels. Sign convention and the budget equation are in `fullband.py`'s docstring
and in every record. `test_full_band.py` covers band cardinality, per-region separation, sign
normalisation and rejection of missing/duplicate terms (`python3 -m unittest discover -s sim/array-slice-bench -p 'test_full_band.py'`).

First record: `records/20261016-015644-361e4f1b-fullband.md` (raw reports in `reports/20261016-015644-361e4f1b-fullband/`, per-region view and per-corner CSV
in `measurements/array-slice-bench/`). The batch job ids are listed in the record.
